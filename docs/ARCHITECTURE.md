# 架构

## 进程与数据流

```
Vue 渲染器（TypeScript、沙盒）
    ├── 同源 HTTP → Node 本地服务 → SQLite / JSON 设置
    │                              └── 有界任务队列 → 独立 OpenCV C++ 进程
    └── 白名单 IPC → Electron → 原生保存、目录打开、主题与语言
```

Electron 先在 `127.0.0.1` 绑定动态端口，再打开窗口。开发时管理 Vite 与代理，打包时从 ASAR 提供静态页面，计算程序位于 ASAR 外的 `Resources/worker`。窗口、资源与数据路径均不依赖当前工作目录。

## 计算协议

Node 启动一项 C++ 子进程，向 stdin 写入一行 JSON，包含应用生成的输入路径、输出目录和经验证的参数快照。stdout 仅使用逐行 JSON：`progress` 报告阶段、`result` 报告结果、`error` 报告语言无关错误代码。标准错误用于诊断。

图片通过字节流解码／编码，Windows 中文路径不直接传给 OpenCV 文件 API。灰度、RGBA、16 位输入统一到计算约定；彩色 JPEG 应用拍摄方向。

每项任务使用 UUID 目录。所有文件准备完毕且计算进程正常退出后，Node 才向 SQLite 发布完成状态。图片和像素矩阵计算使用无参考线掩码，标线图单独生成。

## 队列与恢复

- Node 队列最多四项在途任务，一个 C++ 计算进程。
- 批量前端使用两条上传流水线，一张完成后才继续，不一次读取整批二进制文件。
- 每个批次固定参数快照；单张失败不影响后续任务。
- 可取消尚未导入的等待项，失败项可按原批次参数重新导入。
- 单张计算超过五分钟停止该进程并记录失败。
- 应用退出先关闭 HTTP、停止计算进程，再关闭 SQLite。未完成记录在重启时标记为中断。
- 应用使用单实例锁，避免多个桌面实例并发修改同一用户目录。

设置采用 450 ms 防抖自动保存。服务端验证成功后原子替换 JSON；失败保留上一份有效配置。保存期间新的修改不会被旧响应覆盖，开始批次前会刷新有效设置。

## 历史与导出

SQLite 使用 WAL，版本由 `PRAGMA user_version` 管理。记录保存名称、时间、状态、参数快照、指标、曲线及颜色统计。历史列表不加载整条曲线。

Excel 使用 Node worker thread 逐行写出，ZIP 批量导出流式写入磁盘。批量包附 `summary.csv`，每张图片使用带序号的独立目录，避免同名覆盖。原始输入不会被编辑或删除。

## 语言

`locales/*.json` 同时供 Vue 和 Electron 使用。计算阶段和业务错误传递稳定键；显示时根据语言翻译。日期与数值使用相应语言的 Intl 格式。界面语言不改变分析参数或数据列名。

## 平台构建

CMake 固定并校验第三方源码，静态链接 OpenCV 计算模块。Forge 将计算程序复制到资源目录。分别针对 macOS arm64、macOS x64、Windows x64 运行编译与桌面测试，不使用 Python，也不跨系统复用本地二进制文件。
